# 학원 급여 관리 — 로컬 MVP v1.3

학원 컴퓨터 **한 대**에서 쓰는 출퇴근·급여 관리 웹앱입니다. 선생님은 본인 계정으로 로그인하며 원장님은 전체 조회와 계정·계약 관리를 담당합니다. 로컬 HTTP(`127.0.0.1`)로 실행하며 인터넷이나 LAN에 공개하지 않습니다.

## 준비 및 실행

컴퓨터에 **Python 3.10 이상**을 설치하세요. 최초 한 번은 Python 라이브러리 설치에 인터넷 연결이 필요합니다. 설치 후에는 인터넷 없이 사용 가능합니다.

### Windows

1. ZIP 압축을 풀고 프로젝트 폴더에서 `start_windows.bat`을 더블클릭합니다. (또는 PowerShell에서 `py -3 -m pip install -r requirements.txt` 후 `py -3 app.py`)
2. 실행 창에 서버 주소가 표시되면 Chrome/Edge 브라우저에서 `http://127.0.0.1:8000`을 엽니다.
3. 사용이 끝나면 실행 창에서 `Ctrl+C`로 서버를 종료합니다.

### macOS

1. ZIP 압축을 풀고 터미널에서 프로젝트 폴더로 이동합니다.
2. `bash start_mac_linux.sh`를 실행합니다.
3. 브라우저에서 `http://127.0.0.1:8000`으로 접속합니다.

## 최초 실행과 기존 계정 이전

1. 서버 시작 시 스키마 변경 전에 `data/backups/마이그레이션전_v12_*.sqlite3`를 생성합니다. 백업에 실패하면 이전을 중단합니다. 기존 선생님 ID·근무기록·당시 시급은 보존되며 기존 일반 선생님은 시급제로 이전됩니다.
2. 브라우저의 **최초 원장님 계정 설정**에서 이름·로그인 아이디·비밀번호를 설정합니다. 이 절차는 로컬 컴퓨터에서 한 번만 허용됩니다. 기존 원장님이 있으면 첫 계정의 ID를 유지하여 연결합니다. 이후 원장님 등록·수정은 관리자 인증을 요구합니다.
3. 원장님으로 **선생님 관리 → 정보 수정**에서 기존 계정들의 로그인 아이디와 비밀번호를 설정합니다. 미설정 계정과 비활성화 계정은 로그인할 수 없습니다. 계정 역할 변경은 과거 기록 보호를 위해 제한하며, 다른 역할이 필요하면 새 계정을 등록합니다.
4. 아이디는 영문·숫자·`._-` 3~80자이며 대소문자를 구분하지 않고 고유합니다. 비밀번호는 숫자 4자리(0~9)이며 `0123`처럼 앞자리 0도 유지합니다. 로그인 5회 실패 시 해당 계정은 5분간 제한됩니다. 이름 선택과 아이디 입력은 같은 실패 횟수를 공유하며, 대기 후에는 다시 5회 시도할 수 있습니다. 429 응답의 `Retry-After` 헤더는 남은 대기 시간(초)을 나타냅니다. 비밀번호는 scrypt 해시, 세션 토큰은 SHA-256 해시로 SQLite에 저장합니다. 세션 쿠키는 HttpOnly·SameSite=Strict이며 8시간 후 만료됩니다. 로컬 HTTP이므로 Secure 속성은 사용하지 않습니다.
5. 공용 컴퓨터의 사용자가 바뀌면 상단 **로그아웃**을 누릅니다. 비밀번호·아이디 변경과 비활성화는 해당 계정의 기존 세션을 취소합니다. 마지막 활성 원장님은 비활성화할 수 없습니다.

### 기존 비밀번호를 4자리 PIN으로 재설정

기존 계정의 비밀번호는 자동 변경·초기화하지 않습니다. 기본 PIN도 지정하지 않습니다. 로그인 가능한 원장님은 **선생님 관리 → 정보 수정**에서 대상 계정에 새 PIN을 직접 입력합니다. 비밀번호 변경은 해당 계정의 기존 세션과 실패 횟수를 취소합니다. 비밀번호를 빈칸으로 두면 기존 해시를 유지합니다.

모든 원장님이 이전의 8자리 이상 비밀번호를 사용하여 웹 로그인할 수 없다면, 서버를 종료하고 학원 컴퓨터의 프로젝트 폴더에서 다음 명령을 실행합니다.

```bash
.venv/bin/python reset_pin.py
```

Windows에서는 `py reset_pin.py`를 사용합니다. 기존 원장님의 아이디·비밀번호로 인증한 후, 변경할 계정의 아이디와 새 4자리 PIN을 입력하고 확인합니다. 비밀번호는 터미널에서 표시되지 않으며 명령줄 인자로 전달하지 않습니다. 잘못된 관리자 인증도 5회 실패 시 5분간 제한됩니다. 재설정 전에 SQLite 백업을 만들고 해당 계정의 PIN만 변경하며 급여·계약·근무기록은 유지합니다. 이전 비밀번호 검증은 이 로컬 도구에만 허용되고, 웹 로그인은 계속 4자리 PIN만 받습니다. 기존 관리자 비밀번호를 모르면 재설정하지 않습니다.

## 사용 순서

1. **선생님 관리** → 원장님 로그인 → 신규 등록. 일반 선생님은 이름·전화번호·아이디·비밀번호·급여 유형·금액·적용 시작일을 입력합니다. 원장님은 이름·아이디·비밀번호만 입력하며 급여 대상에서 제외됩니다.
2. **선생님** → 활성 일반 선생님 목록에서 본인 이름 선택 → 비밀번호 입력 → 달력에서 날짜 선택 → 출퇴근 시각 입력·수정·저장. 동명이인은 표시된 로그인 아이디로 구분합니다.
3. 달력 `◀` `▶` 버튼으로 월을 바꿉니다. 월·날짜 선택이나 저장은 브라우저 방문 기록에 추가되지 않습니다.
4. **원장님** → 관리자 로그인 → 선생님별 월간 현황 → 읽기 전용 조회 → 급여명세서 미리보기 → **PNG 이미지 다운로드**. FastAPI에서도 원장님의 근무기록 변경 요청을 차단합니다.
5. **선생님 관리** → 계정·계약 수정, 비활성화·재활성화, 학원 정보 설정, Excel 백업·복원. 원장님 세션이 있으면 재인증하지 않습니다. 일반 선생님은 서버에서도 접근할 수 없습니다.

## 계산 방식과 계약 이력

- 하루 근무기록은 최대 1건입니다. 분 단위로 기록하며 퇴근이 출근보다 늦어야 합니다. 자정 넘김과 별도 휴게시간은 지원하지 않습니다.
- **시급제:** `floor(sum(근무분 × 근무일 적용 시급) / 60)`. 기존 v1.2처럼 월 합계에서 한 번만 원 미만을 버립니다.
- **일급제:** 유효한 근무기록 1일당 당시 계약 일급 전액을 합산합니다. 시간 수정은 근무일수를 늘리지 않습니다.
- **월급제:** 계약이 온전히 유지된 달에는 기록 유무·근무시간과 무관하게 월 고정급 전액을 표시합니다. 출근일수와 근무시간은 별도로 집계합니다. 중도 시작·종료·금액 변경은 자동 일할 계산하지 않습니다. 계약이 종료된 이후의 완전한 미재직 달은 0원입니다.
- 새 근무기록에는 **근무일에 유효한** 계약 유형·금액·공제율을 저장합니다. 기존 기록을 수정하면 저장된 적용 계약을 보존합니다.
- 계약은 적용일과 함께 추가되며 기존 이력을 덮어쓰지 않습니다. 적용일은 마지막 계약일 및 이미 저장된 근무기록보다 뒤여야 합니다. 월급제가 포함된 변경은 지난달 이전으로 소급할 수 없습니다.
- 같은 달에 급여 유형이 바뀌거나 월급제 계약·재직 상태가 중도 변경되면 **정산 확인 필요**로 표시하고 세전·공제·실수령액의 자동 산정을 보류합니다. 원장님 합계에는 산정 가능한 금액만 포함하며 미확정 항목이 있음을 알립니다.
- 결근 등 별도 조정이 필요하면 **선생님 관리 → 정보 수정 → 해당 선생님 → 월별 정산 확인**에 사유를 저장합니다. 근무기록을 바꾸지 않고 해당 월을 정산 보류로 구분합니다. 사유를 비우면 수동 표시만 해제하며, 계약 변경으로 자동 감지한 보류는 유지됩니다. 확정 금액을 입력하는 조정 기능은 포함하지 않습니다.
- **공제액:** `floor(세전급여 × 330 / 10000)`, **예상 실수령액:** 세전급여 − 공제액. 계약·기록에 공제율 필드를 보존하여 향후 확장할 수 있습니다. 현재는 3.3%만 지원합니다. 실제 지급 전 계약·소득 구분에 따른 적용 여부와 정산 내용을 확인해 주세요.

## 데이터 저장 및 자동 백업

- 실제 원본: `data/academy_payroll.sqlite3` (SQLite).
- 저장/수정/비활성화 직후 자동 갱신: `data/backups/급여관리_최신.xlsx` 와 `급여관리_최신.sqlite3`.
- 첫 저장 시 생성되는 날짜별 보관본: `data/backups/YYYY-MM-DD/` 안의 Excel 및 SQLite 스냅샷. **날짜별 보관본은 그날 첫 변경 시점의 스냅샷**이므로 최신 상태는 `급여관리_최신.*`를 사용하세요.
- Excel에는 계정 기본정보·로그인 아이디·급여 계약 이력·재직 변경·정산 확인·근무기록·월별 요약을 포함합니다. **비밀번호 해시와 세션 비밀정보는 포함하지 않습니다.** 전체 SQLite 백업에는 인증 정보가 있으므로 별도로 안전하게 보관하세요.
- 복원: 프로그램에서 만든 `.xlsx` 파일 선택 → 전체 교체 확인 → 기존 DB의 `복원전_안전백업_*.sqlite3` 생성 → 검증 후 교체. v1.2 Excel도 시급제로 복원할 수 있습니다. 현재 관리자 계정은 보존하며 ID가 충돌하면 교체를 중단합니다. 일치하는 기존 계정만 로그인 정보를 유지하고 새로 복원된 계정의 비밀번호는 원장님이 다시 설정해야 합니다. 복원 후 모든 세션을 취소하므로 다시 로그인해야 합니다. `월별급여` 시트는 참고용으로 복원 시 다시 계산됩니다.
- **중요:** 동일 디스크의 자동 백업은 디스크 고장 대응책이 아닙니다. 주기적으로 `data` 폴더 전체를 USB·외장 SSD·접근이 통제된 별도 저장소에 복사하세요.
- 삭제/캐시 정리와 무관하게 SQLite는 프로젝트 폴더에 파일로 보관됩니다. 단, 폴더 자체를 지우면 사라집니다.

## 주요 파일

```text
academy-payroll-mvp/
  app.py                 # FastAPI, SQLite, Excel 자동 백업/복원, 급여 계산
  payroll_v13.py         # 추가형 마이그레이션, 비밀번호 해시, 계약별 계산
  requirements.txt
  start_windows.bat
  start_mac_linux.sh
  static/
    index.html           # 웹앱 진입점
    styles.css           # 반응형 디자인
    app.js               # 화면 이동, 달력, PNG 급여명세서
  tests/test_workflow.py # 통합 테스트
  data/                  # 첫 실행 때 생성 (.gitignore 대상)
```

화면에서 보이는 학원 로고는 기본 교육용 심볼이며 학원명은 `선생님 관리 > 학원 정보`에서 수정할 수 있습니다. 실제 로고 이미지 적용은 향후 맞춤 디자인 작업으로 교체 가능합니다.

## 테스트

기존 급여·백업 회귀 테스트, 권한·세션·마이그레이션·세 가지 급여 계산 테스트, 실제 브라우저 테스트를 포함합니다. 아래 개발용 검증 명령을 사용하세요.

## 브라우저 화면 이동

별도 라우팅 라이브러리 없이 Hash Routing을 사용합니다. 브라우저 뒤로가기·앞으로가기와 트랙패드의 브라우저 탐색 제스처는 실제 방문 순서를 따릅니다. 직접 URL 접속과 새로고침도 해당 화면을 엽니다.

| URL | 화면 |
| --- | --- |
| `/#home` | 메인 |
| `/#teachers` | 선생님 목록 |
| `/#teacher/{id}` | 선생님 근무기록 입력 |
| `/#director` | 원장님 목록 |
| `/#director/teacher/{id}` | 읽기 전용 개인 조회 |
| `/#director/teacher/{id}/payslip` | 급여명세서 |
| `/#management` | 선생님 관리 (기존 신규 등록 탭) |
| `/#management/edit` | 정보 수정 대상 목록 |
| `/#management/edit/{id}` | 개별 정보 수정 |
| `/#management/status` | 비활성화·복구 |

신규 등록은 기존 관리 첫 화면과 동일하므로 별도의 가상 방문 기록을 만들지 않습니다. 로고는 홈으로 이동하며, 같은 URL의 중복 이동은 기록하지 않습니다. 월·날짜 선택과 저장은 URL이나 방문 기록을 바꾸지 않습니다. 선택한 월은 현재 세션 상태이며 새로고침하면 이번 달로 돌아갑니다. 잘못된 URL은 홈, 존재하지 않는 선생님은 해당 목록으로 현재 기록을 대체합니다.

### 개발용 검증

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m playwright install chromium
PAYROLL_DATA_DIR=$(mktemp -d) .venv/bin/python -m pytest -q
```

설치된 Chrome으로 검증하려면 `PLAYWRIGHT_CHANNEL=chrome` 환경 변수를 추가합니다. Playwright가 없으면 브라우저 테스트는 생략됩니다. 테스트는 임시 디렉터리에서 실행되어 실제 SQLite와 백업을 변경하지 않습니다.

## Windows 배포판 (Python 설치 불필요)

기존 개발용 실행 방법과 별도로 `AcademyPayroll.exe` 단일 실행 파일을 제공합니다.
현재 저장소가 빈 상태에서 시작되어 배포 브랜치에만 업로드했으며, 아래 다운로드는
**Windows package 워크플로가 성공한 이후** 사용할 수 있습니다.

### 다운로드·실행·종료

1. GitHub 저장소 → **Actions → Windows package → 성공한 실행**을 엽니다.
2. **Artifacts → AcademyPayroll-windows-x64-…** ZIP을 다운로드하고 압축을 풉니다.
   Artifact 다운로드에는 GitHub 로그인이 필요하며 보관 기간은 30일입니다.
   `v*` 태그 빌드는 검토용 Draft Release도 생성합니다. 공개 Release는 검토 후 게시합니다.
3. `AcademyPayroll.exe`를 더블클릭합니다. 서버 준비가 끝나면 기본 브라우저가 열립니다.
   Python·pip 설치나 인터넷 연결이 필요하지 않습니다. Windows 64비트 전용입니다.
4. 최초 화면에서 원장님 이름·아이디·**숫자 4자리 PIN**을 직접 설정합니다.
   기존 DB를 이전했다면 기존 비밀번호를 사용합니다. 기본 비밀번호는 없습니다.
5. 실행 중인 **학원 급여관리** 창에서 **프로그램 종료**를 누르거나 창을 닫습니다.
   브라우저를 닫아도 서버는 계속 실행됩니다. 동일 EXE를 다시 열면 기존 서비스에 접속합니다.

서명하지 않은 EXE에 Windows SmartScreen 경고가 나타날 수 있습니다. 저장소와 빌드 결과를
확인하고 조직의 실행 정책을 따라야 합니다. 다운로드에 동봉한 SHA256.txt로 파일을 비교할 수 있습니다.

### 데이터 저장 위치·이전·업데이트

배포판은 Windows 사용자 프로필의 **LocalAppData\\AcademyPayroll**을 사용합니다.
탐색기 주소창에 `%LOCALAPPDATA%\\AcademyPayroll`을 입력하세요.

- 원본 DB: `academy_payroll.sqlite3`
- Excel·SQLite 자동 백업: `backups\\급여관리_최신.xlsx`, `backups\\급여관리_최신.sqlite3`
- 날짜별 백업: `backups\\YYYY-MM-DD\\`
- 오류 로그: `logs\\errors.log` (최대 512KB × 현재 파일과 보관본 3개)

**이전 소스 버전에서 처음 배포판으로 이동할 때:** 이전 서버와 배포판을 모두 종료하고,
기존 `data` 폴더 전체를 별도 위치에 안전하게 복사하세요. 그런 다음 기존 `data` 폴더의
내용물(DB와 backups 폴더)을 `%LOCALAPPDATA%\\AcademyPayroll`로 복사합니다.
목적지에 이미 DB가 있으면 덮어쓰지 말고 어느 것이 실제 운영 DB인지 먼저 확인하세요.
복사 후 EXE를 실행하면 기존 ID·PIN 해시·급여·계약을 유지한 채 기존 마이그레이션을 적용합니다.
Excel만 복원하면 새 계정의 PIN은 포함되지 않으므로 **기존 비밀번호 유지에는 SQLite 이전이 필요**합니다.
폴더를 복사하지 않고 최초 실행하면 새 DB가 생성되며, 기존 폴더의 DB는 수정하지 않습니다.

업데이트는 프로그램 종료 → 데이터 폴더 전체의 외부 백업 → 새 EXE로 교체 → 재실행 순서입니다.
EXE 위치와 압축 해제 임시 폴더에는 운영 데이터를 저장하지 않습니다.
`PAYROLL_DATA_DIR`은 개발·테스트용이며 배포판은 이를 무시합니다.
Windows 사용자 계정이 바뀌면 데이터 경로도 바뀝니다. Windows 자체 계정과 파일 접근 권한을 관리하세요.

### 백업·복원

기존 **선생님 관리 → Excel 백업·복원**을 그대로 사용합니다.
원장님 로그인 후 백업을 다운로드하고, 복원 전에는 현재 DB의 안전 백업을 자동 생성합니다.
복원 후 다시 로그인해야 합니다. DB 전체 복사에는 PIN 해시가 포함되므로 외부 공개하지 마세요.
주기적으로 프로그램을 종료하고 데이터 폴더 전체를 별도 저장소에 복사하세요.

### 오류 해결

- 창은 열렸지만 브라우저가 안 열리면 **급여관리 열기**를 누릅니다.
- 8000 포트가 사용 중이면 8001~8005 중 사용 가능한 포트로 자동 이동합니다.
  모두 점유되면 기존 프로그램을 정상 종료한 뒤 다시 실행하세요.
- 이미 실행 중인데 열리지 않으면 기존 실행 창을 확인하세요. 강제 종료 후에는 다시 실행할 수 있습니다.
  잠금 파일 자체는 남아도 OS 잠금이 풀리므로 수동 삭제할 필요가 없습니다.
- 오류가 나면 데이터를 삭제하거나 초기화하지 말고 `logs\\errors.log`와 발생 상황을 확인하세요.
  로그에는 요청 내용·PIN·급여·DB 내용·예외 메시지를 기록하지 않습니다.
- 데이터가 비어 보이면 Windows 사용자 계정과 위의 이전 절차를 확인하세요.
  기존 DB 위에 새 DB를 덮어쓰지 마세요.
- 기존 장문 비밀번호의 로컬 PIN 변경 도구는 개발용 `reset_pin.py`에 남아 있습니다.
  EXE에는 별도 PIN 우회·초기화 기능을 넣지 않았습니다.

### 빌드·검증

실제 백엔드는 Flask가 아닌 FastAPI입니다. API 및 기존 UI를 유지하기 위해
Waitress와 a2wsgi의 ASGIMiddleware를 사용합니다. 서버는 127.0.0.1에만 바인딩합니다.

Windows x64 Python 3.12 환경:

```powershell
python -m pip install -r requirements-build.txt
python -m playwright install chromium
python -m pytest -q
python scripts/verify_distribution.py
python -m PyInstaller --clean --noconfirm AcademyPayroll.spec
python scripts/verify_distribution.py dist/AcademyPayroll.exe
python scripts/smoke_executable.py dist/AcademyPayroll.exe
```

Smoke 검증은 운영 PC가 아닌 **데이터가 없는 깨끗한 Windows 테스트 사용자**에서만 실행하세요.
가상 원장님을 생성하므로 기존 데이터 폴더가 있으면 즉시 중단합니다.
CI는 테스트 실패 시 빌드를 중단하며, 빌드 후 EXE를 실제 실행해 리소스·중복 실행·종료·재시작·DB 보존을 확인합니다.
버전·실행 번호·커밋별 Artifact와 사용한 의존성 버전을 보관합니다.
단일 EXE는 시작할 때 임시 폴더에 리소스를 추출하며 운영 DB는 고정 경로에 남습니다.
실제 학원 PC에서 백신 차단·추출 실패·시작 지연이 확인되면 onedir 전환을 검토합니다.
macOS 빌드는 Windows 실행 검증을 대체하지 않으며 Windows EXE는 Windows Runner에서 생성해야 합니다.
